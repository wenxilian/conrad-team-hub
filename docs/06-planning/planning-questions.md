# 项目执行：立项、阶段评审、权属与安全

一个有意思的点子，落到实际项目中，会同时遇到时间、预算、设备、安全和协作问题。提前讨论这些限制，可以帮助团队选择一个真正能完成、能验证的范围，也避免等到提交前才发现资源或权属没有说清楚。

这一页从立项前的八个问题开始，接着安排阶段评审，并讨论保密、知识产权与测试安全。大家可以用这些问题组织一次完整的立项讨论，再把结论转成每周的任务和调整条件。

## 1. 立项前的八个问题 {#questions}

1. **赛季与队伍确认**：组队报名截止、成员替换规则、coach、国内站/全球站的路径。
2. **保密/IP**：技术来源、专利申请时点、赛事公开展示的披露边界、成员及机构权属。
3. **能力互补**：工程、软件、测试、商业、英文路演的职责，核心学生能否真实投入。
4. **成人协助范围**：成果归属、学生贡献、外部工程师代码/设计与工具来源。
5. **安全合规**：航空监管、试验地点、室内/室外、消防类高风险场景、保险与责任。
6. **真实采购者**：家庭受益不代表家庭付费；可能是物业、园区、企业、公共机构。
7. **最小可验证创新**：不要在机械、传感、AI、通信、飞控上同时无限扩张；界定一个可测核心。
8. **预算与持续性**：研发设备、试验、返工、差旅、赛事费用及未获奖后的继续开发。

采用三个阶段性评审 Gate 1 (资格、团队、权属、安全、创新范围)、Gate 2 (技术性能与用户需求)、Gate 3 (参赛材料、学生独立答辩、公开内容和证据一致性)。每次评审可决定继续、收缩范围或暂停，留下原因。

公开、内部、核心秘密三层信息隔离。公共网站只发布通用案例、教学工具和确认可公开的信息；严禁上传未经批准的具体工程架构、数据、个人信息或保密算法。

## 2. 八项风险与缓解方案 {#risks}

| 风险 | 典型问题 | 筹划阶段做什么 |
|---|---|---|
| 报名时间 | 团队尚未锁定，错过 Activation | 立即核对目标赛季、团队人数与锁定规则 |
| 知识产权 | 成人前期研发或第三方专利 | 贡献盘点、权属咨询、披露审批 |
| 学生主导 | 技术和商业大多由导师完成 | 学生决策、独立实操、日志与代码版本 |
| 合规安全 | 无人机测试、模拟与野火场景 | 先做安全替代实验、检查本地法规 |
| 真实采购方 | 误把被保护家庭视为购买方 | 分别访谈使用者、付费方和决策者 |
| 创新分散 | 每个模块都有新想法，无法验证 | 锁定最小可验证创新 |
| 资源预算 | 材料与测试反复失败 | 分阶段预算与测试冗余 |
| 项目可持续 | 未获奖就中断 | 明确学习成果、可迁移资料和退出机制 |

## 3. 三个 Gate：继续、收缩或暂停 {#gates}

**Gate 1 (现在)**：有无学生主导的核心创新？队员与导师身份是否清楚？已有成果是否能合法使用？有无安全测试条件？什么内容可公开？

**Gate 2 (第一轮原型与市场调研后)**：是否可重复实现关键功能？改进与基准比是否可测量？目标客户是否存在？成本和可靠性是否出现无法克服的约束？若不通过，应缩小范围或改变策略，而非只延长工期。

**Gate 3 (正式提交前)**：英文文书、网站、演示、实验结果和商业数字是否一致？学生能否不看导师回答关键技术、成本和用户问题？来源、版权和保密范围是否清楚？

## 4. 权属、保密与公开披露 {#ip}

先期成果按学生独立开发、成人建议、成人直接开发、第三方开源或购买、归属未查清五类盘点。每项写清来源、实际作者、使用许可和学生新增工作。

| 信息层 | 示例 | 保存与审批 |
|---|---|---|
| 公开 | 通用问题、公开案例、已批准的非敏感指标 | 进入学习网站前审查 |
| 内部 | 设计过程、初测、访谈匿名记录 | 受控团队空间 |
| 核心秘密 | 未保护的创新、关键算法、细图和个人信息 | 最小权限，单独审批 |

官方规则提示公开展示不属于保密。专利程序、地域要求和权属需要针对实际项目咨询；网站不提供确定法律结论。内部技术不应为了做一个好看的网站而进入公开仓库。真实参赛产品网站和当前资料站分开建设。

来源：[全球规则页](https://conrad.spacecenter.org/the-challenge/rules-and-regulations/)，核查于 2026-10-12。美国队伍相关专利要求不可直接套给所有地区。

## 5. 安全测试与应急方案 {#safety}

无人机、火情和道路机器人涉及不同监管与责任，开始前由成人监督确认场地、设备、许可和应急方案。本页提出教学安全边界，不替代当地现行法规与专业审查。

| 项目形态 | 第一版安全测试 | 暂不进行 |
|---|---|---|
| FireAIDSS | 公开数据、合法模拟、非燃烧替代场景 | 自行制造真实火情、无授权飞行 |
| Aphelion | 台架、限幅、机械防护、断电保护 | 无限制加载或靠近高速部件 |
| RescueBot | 封闭授权场地、低速、物理急停 | 开放道路测试 |
| 水下通信 | 受监管可控测试、独立安全方案 | 用未经验证原型承担潜水安全保障 |

实验前检查供电、急停、场地隔离与人员责任；异常时先停机。日志保留故障触发条件、停机距离或反应时间。测试场地、保险和责任需在具体项目内部确认。

## 6. 内部可行性报告目录 {#feasibility}

一份 5–8 页内部报告可包含项目边界、参赛资格、学生与成人贡献、现有成果、最小可验证创新、试验路线、安全、商业访谈、预算、阶段评审和退出条件。不把这种内部报告自动发布到公开资料站。

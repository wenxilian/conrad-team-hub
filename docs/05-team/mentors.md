# 团队与导师：学生主导、成人边界和协作记录

考虑参加时，我也在想：同学之间怎样分工，遇到超出已有知识的问题，家长和老师可以怎样帮助？我想得到指导，也想有机会自己动手、作决定，并能在展示时讲清楚自己做过的工作。

这里整理了学生与成人的职责、指导和代做的区别，以及记录贡献的方法。它可以作为组队前的讨论材料，帮助大家提前说清楚各自承担什么。

## 1. 成人可以指导什么 {#mentors}

具不同专长的成人导师可以提供指导与资源，学生应负责实际项目及提交材料。

辅导通常可包括：讲授研究方法、示范如何设计客户访谈、帮助获取合规的测试资源、提供安全监督、检查公式/分析的逻辑、评论英文初稿、模拟答辩。但学生应主导研究问题、设计、实施、数据分析、具体提交文稿和展示。这些是我们讨论协作方式的建议；coach 的具体职责、AI 工具与成人参与要求，仍以当届官方规则为准。

典型边界问题：

- 家长能提出「应分析 TAM/SAM/SOM」的框架，但不宜代学生完成全部市场数据与结论。
- 工程师家长可讲授控制与安全，不宜把成人事先完成的核心结构包装成学生独立发明。
- 学生可用开源代码和 AI 辅助，但须遵循当届的披露、署名和原创性规定，能解释代码做什么。
- 商业分析里的数值与模拟表若由成人做出、学生无法推导，现场 Q&A 风险明显。
- 如果已有前期成果，应清点学生、成人、学校/实验室各自贡献，以及 IP 权属。

团队可以用工程与商业任务记录、Git 提交、实验日志和导师反馈，回看每位成员实际做了什么。这样的记录也能帮助学生准备答辩；至于赛事是否有强制日志检查，现有资料尚未确认。

商业学习可安排约 20–30 小时：市场用户研究、微观经济与基础财务、商业模式、英文表达和答辩。具体时长是教学建议。

## 2. 具体情境：指导与代做如何区分 {#scenarios}

#### 可以合理提供的支持

- 商业导师讲授 TAM/SAM/SOM、固定和可变成本、市场调查伦理、盈亏平衡等，给学生提建议并指出公式或口径错误。
- 工程导师传授安全规范、介绍 CAD/控制基本方法、示范仪器测量，帮助获取安全场地与公共资料。
- 家长联系潜在访谈对象、协调设备采购和场地，但访谈问题、数据整理和最终结论由学生执行。
- 导师阅读学生撰写的 Innovation Brief，指出未解释的数字和自相矛盾的论证，学生自行修订。

#### 存在明显边界风险的做法

- 成人实际设计核心技术，学生只在表面上运行现成软件，仍宣称为学生原创。
- 家长代做全部市场调查、财务模型或英文商业文字；学生只负责排版和背稿。
- 工程顾问完成实物功能与测试，学生无法解释传感器、控制机制及数据来源。
- 为使项目看起来完美，仅选取一次成功演示而隐瞒失败、虚构访谈或改造原始数据。

应依据目标赛季的官方规则确定具体限制，而不是把上述教学建议说成组委会原话。**项目团队最好设立 `student-contribution-log`，每次学生实际完成任务后才更新，导师只写其指导和反馈，禁止事后编造。**

#### 组委会如何发现成人代做？

现场答辩的技术细节、数字来源、实际失败案例、开发决策追问可能揭示学生是否熟悉项目。提交材料的一致性、过程证据及学术诚信申报也可能有帮助。但不能断言组委会必然有某种自动查重、全过程审计或随机访谈机制，除非在官方规则中查证。正确做法是让项目真实由学生主导，不要把留下证据理解为「应付检查」。

## 3. 成员、职责与会议节奏 {#roles}

学生团队按目标赛季规则核查人数与年龄 (曾讨论 2–5 人、13–18 岁)。建议工程结构/机械、软件与数据、实验验证、市场商业、英文传播五类职能，根据 3–5 人的实际人数交叉安排。不要以五个岗位必须分别对应五个人为前提。

学生选拔时设实际小任务：技术候选人读取公开传感器数据并绘图或解释已有结构，商业候选人搜集两个真实竞品并说明价格与维护费，写作候选人以英语表达一段包含数据来源的论证。考察持续投入、沟通和质量意识，而不单看奖项或竞赛经历。

**管理节奏**：每周学生会议，汇报已完成文件、问题和下一周任务；每两周一次导师审查，不代替学生项目决策。每个任务记录负责人、交付文件、测试证据、预计完成日。家庭可以先选择每周可投入时间区间，而不披露详细私人日程。

## 4. 先期成果、学生贡献与保密 {#contributions}

对于已有先期成果的项目，应梳理已有工程项目成果：代码、零件、机械图、实验记录、技术方案、调研文档、构想、采购、导师实质贡献，以及所有人的权利边界。分成：学生独立开发、成人建议、成人直接开发、第三方开源/购买、归属尚未查清。对每一项标明将来如何引用，以及学生计划进一步独立开发什么。

**保密清单**：公开层只放问题、应用、非敏感指标；内部层放设计与初步测试；严格保密层放未保护的关键创新与算法。完整具体方案不应为了建站进入公开 GitHub 仓库。提交组委会前先核实相关材料是否公开、评委保密承诺是否覆盖该阶段、是否需要专利咨询。

## 5. 家长与学生完整问答 {#faq}

**Q：学生要达到大学几年级的水平？** 商业部分近似微观、Marketing 和管理会计入门层级，工程视选题可从高中进阶到大学工程课程设计乃至更高专项知识；不要求所有队员都具备全部能力。

**Q：是否必须有可以卖的成熟产品？** 不必；但原型成熟度要与声称的性能匹配，概念和演示不得假冒实测。

**Q：家长可否替学生写商务计划？** 不宜。可以教授方法、指出错误、提供资源，正式文书及关键分析由学生完成。

**Q：是否可以使用开源工具、AI 和第三方模型？** 可以从成熟平台出发，但具体赛季关于 AI 和外部贡献的规则要核实，必须记录来源，并能解释学生自己的新增贡献。

**Q：项目保密如何处理？** 对内明确可公开材料；对外不披露没有保护的技术秘密；网站和 PDF 仅整理公开学习材料。组委会提交材料需单独审查。

**Q：没有获奖还有什么收获？** 可保留工程程序、实验设计、客户访谈、英文写作和团队协作等真实成果；不能用获奖保证大学录取。

# 资料与来源：官方档案、核查、原图线索与缺口

讨论中遇到不确定的规则或数字时，我们需要能找到它从哪里来。这一页集中保存官方入口、来源核查、图片出处和仍待确认的资料，方便家长、学生和老师在同一份依据上继续交流。

公开介绍能帮助我们了解项目，但实验结论还需要原始数据和具体条件。阅读时可以把赛事规定、团队申报和我们的练习算例分别看待；找到新的资料后，也可以据此补充或修正。

## 1. 来源方法与逐项事实核查 {#audit}

本站依据此前的详细讨论资料整理。现有资料不是逐字聊天导出，部分原始图片与实验细节仍需要补充。赛事规则随季更新，报名前应再次核对正式指南与平台。

AI 可辅助检索、整理和检查格式，不能替代精读、技术验证与责任判断。所有实质性能和财务判断都需要可检查证据。

## 6. 术语与概念 {#glossary}

| 术语 | 含义与容易混淆之处 |
|---|---|
| PoC | 概念验证，能运行不等于可靠 |
| Baseline / Benchmark | 基准方案与同条件对比 |
| PINN | 物理信息神经网络，提到名称不等于完成验证 |
| PID | 比例、积分、微分控制 |
| BOM | 物料清单，原型成本不等于量产和售后总成本 |
| TCO | 总拥有成本，须说明年限、贴现与残值 |
| TAM / SAM / SOM | 总体、可服务、可获得市场，需统一口径 |
| Contribution | 边际贡献，尚未扣固定成本 |
| SaaS | 软件服务订阅，注册用户不等于付费用户 |
| Gate | 阶段评审，可决定继续、收缩或暂停 |
| Coach | 成人指导者，不代替学生完成材料 |
| Innovation Brief | 当届指定章节和词数的创新说明 |

## 7. 网站与单源双部署 {#website}

学习网站保留完整案例、公式和问答，PDF 可作为补充。正文在 Markdown 中维护，同一份源文件构建两套静态目录；不要手工维护两份会漂移的内容。

GitHub Pages 使用仓库子路径，阿里云独立域名使用根路径；所有本地资源以相对路径加载。网站采用 MkDocs + Material，搜索、公式与模拟器资源本地化，不依赖 Google Fonts。

开发在 dev，正式审核版本在 main；GitHub Actions 只发布 main。公开网站只包含审核后的 docs 和必要程序。原始资料、内部讨论、真实技术、个人信息和密钥均排除。

本地验收检查手机及桌面、公式、宽表格、深层链接、搜索、脚本错误和外部资源请求。浏览器在线预览与双击 HTML 不相同；正式站应通过 HTTP 服务读取。PDF 导出另行校验，不能把交互控件打印成无解释空白。

# 工程与技术：从编程到原型验证

读往届项目时，我很好奇：高中生怎样把无人机、控制系统或 AI 模型做成一个可以展示的方案？进一步了解后，我觉得还需要问清楚：哪些能力要自己学，哪些成熟工具可以借用，又怎样证明自己的改进有效？

这一页整理了编程与系统集成的能力要求，并用 FireAIDSS、Aphelion 和 RescueBot 作参照。后面的测试方法和证据清单，帮助我理解一次成功演示之外还需要准备什么，也供有相似问题的同学参考。

## 1. 编程与系统工程的要求 {#programming}

总体判断：通常较强高中生经过训练可完成大学低年级工程课程设计级别原型；更复杂的无人机集群、控制系统涉及高阶知识，但可通过使用成熟平台、限定核心创新范围控制难度。赛事不是统一要求工业级完成品。

编程分层：

- L1 基础：Python 函数、循环、文件读写、调试和可视化。
- L2 工程：传感器数据、硬件控制、模块化、异常处理。
- L3 集成：控制回路、通信、日志、端到端运行及基本自动化测试。
- L4 优化：实验对照、算法基准、误差和可靠性评估。团队总体目标建议 L3，创新核心争取 L4。

测试四层：Proof of Concept (功能可运行)、Performance Testing (有指标)、Benchmarking (与 baseline 比较)、Reliability Testing (扰动/重复/异常条件)。技术报告应保存失败试验，而不是只剪辑一次成功视频。

对于工程类案例：FireAIDSS 偏数据、AI 与多机模拟；Aphelion 偏机电、控制与功耗测量；RescueBot 偏移动机器人、嵌入式、传感与安全。学生必须能解释自己写的代码、借用框架/开源组件的来源、关键结果如何计算。可以采用现有 PX4/ArduPilot、Arduino/ESP32、Python 等工具，但不应暗示每行程序都由学生原创。

建议工程资料目录：`engineering-design.md`、`hardware-bom.xlsx`、`src/`、`tests/`、`data/`、`engineering-validation.md`、`demo/`；这些为**保密项目内部工作区的建议**，不是公开学习网站内容。

## 2. L1–L4 能力框架 {#levels}

| 层级 | 能力 | 可交付成果 | 不能用什么替代 |
|---|---|---|---|
| L1 基础编程 | Python 函数、循环、文件和绘图 | 传感器数据读取、图形与基础脚本 | 演示别人写好的现成程序 |
| L2 工程编程 | 嵌入式 I/O、模块化与故障处理 | 单模块独立运行 | 只连线但不理解控制逻辑 |
| L3 系统集成 | 多模块交互、日志、测试 | 端到端可重复原型 | 一次剪辑后的视频 |
| L4 工程优化 | 对照、指标、复杂工况验证 | 有定量证据的改进 | 未披露基准的百分比提升 |

团队整体应以 L3 为合理目标；创新核心尽可能达到 L4。不要求每位学生掌握全部模块，但至少两人能够独立解释关键软件。分级是项目建议，**不是官方认证等级**。

## 3. FireAIDSS：数据、预测与模拟 {#fireaidss}

#### 技术管线

`公开或合法采集的图像/热成像 + 风速/风向/地形 → 时间同步与位置配准 → 火情区域提取 → 简化传播基线 → 改进预测模型 → 风险地图 → 模拟监测任务调度`。

第一阶段可先完成离线图像处理；第二阶段使用公开数据进行传播预测；第三阶段仅在模拟环境展示多机任务调度。不应先承诺已经实现多无人机自主实飞。PINN 的具体实现尚待进一步资料确认。作为一个可探讨的技术方向，PINN 是物理信息神经网络，教学时要说明偏微分/物理约束与损失函数的关系，但高中生不必从头研发复杂物理求解器。

#### 必要编程栈

Python、NumPy、Pandas、OpenCV、Matplotlib 作为入门；可根据需要加入 PyTorch。飞行任务模拟可参考 PX4 或 ArduPilot，但必须确认开源许可、安全边界、硬件匹配及学生是否真正理解调用方式。

#### 试验设计

1. 图像检测：测试集中含不同光照、烟雾背景，记录 TP、FP、FN，计算 Precision、Recall 和 F1；避免训练数据与测试数据混用。
2. 传播预测：采用有标注时间序列，比较简单恒速传播基准与改进模型，用 MAE、RMSE、空间重合度评价；说明数据来源和预测时间跨度。
3. 路径规划：在模拟网格上模拟单机与多机监测，比较覆盖率、耗时、通信约束。
4. 总体响应：输入传感数据至输出风险图的端到端时延，至少包括平均和最差情况。
5. 失败案例：烟尘遮挡、传感器丢帧、定位偏差和异常输入如何处理；标示当前无法保证的性能。

火灾相关验证必须采用公开火情数据、合规模拟或非燃烧模拟场景，不能自行制造野火或在无授权环境开展飞行。

## 4. Aphelion：闭环控制与能耗 {#aphelion}

#### 工程路径

从目标需求出发确定自由度、负载、速度与精度；设计 CAD 结构；制造低成本原型；安装驱动电路与角度反馈装置；搭建闭环控制；重复测试定位、响应与能耗。

在一维轴上可用比例、积分、微分反馈的组合，误差 $e(t)=r(t)-y(t)$，控制量：


$$
u(t)=K_{p}e(t)+K_{i}\int_{0}^{t} e(\tau)d\tau+K_{d}\frac{de(t)}{dt}
$$

<div class="relationship-figure"><div class="diagram-row"><div class="diagram-node">目标角度 r(t)</div><span class="diagram-arrow">→</span><div class="diagram-node">误差 e(t) 与 PID<br><small>比例、积分、微分</small></div><span class="diagram-arrow">→</span><div class="diagram-node">驱动与执行器<br><small>安全限幅、停止保护</small></div></div><div class="feedback-label">↑ 编码器测得 y(t) → 回到控制器，更新 e(t)=r(t)−y(t)</div><div class="diagram-support">同任务测试：定位误差 · 响应时间 · 超调 · 重复性 · 负载 · 总能量</div><p class="figure-caption">教学闭环控制示意，不是获奖团队的原始结构图。参数调试不能替代设备保护。</p></div>


解释目标角度、实际角度、误差、超调、稳定时间，不只把公式贴出来。若涉及多轴，增加旋转矩阵、基本运动学与限位逻辑。

#### 控制系统程序模块

- 传感器：读取编码器角度、校准、检查越界和断连。
- 控制器：计算误差，输出适当控制信号；设限幅、安全退出。
- 记录器：写出时间、设定角度、实际角度、电流、电压和状态码。
- 计算程序：用 Python 绘制期望与实际轨迹、误差曲线、响应时间。

#### 推荐测试矩阵

| 指标 | 方法 | 报告 |
|---|---|---|
| 定位 | 多个目标角度重复指令 | 平均、最大绝对误差 |
| 动态响应 | 阶跃命令 | 上升时间、稳定时间、超调 |
| 重复性 | 同一目标执行 10–20 次 | 标准差、失败次数 |
| 载荷 | 安全范围内增加负载 | 误差变化、稳定极限 |
| 能耗 | 同任务、同负载下积分 $VI$ | Wh，不只瞬时 W |
| 结构 | 实测质量与几何尺寸 | 与基准装置比较 |

公式 $E=\int_{0}^{T} V(t)I(t)\,dt$，明确测量时间与采样频率。历史讨论出现的 20%、61.8%、71% 是团队公布比较结果，项目报告本身应披露基准和重复测试，不能从摘要推出全部工况有效。

### 公式符号与能量单位
目标角度为 $r(t)$，测得角度为 $y(t)$，误差 $e(t)=r(t)-y(t)$，控制输出为 $u(t)$。$K_{p}$、$K_{i}$ 和 $K_{d}$ 分别是比例、积分、微分增益。增益需在安全限幅下调试，模型不能代替设备保护。
电压 $V(t)$ 以 V、电流 $I(t)$ 以 A、时间以秒计时，$\int_{0}^{T}V(t)I(t)\,dt$ 的单位是 J；换成 Wh 需除以 3,600。这里的 $T$ 是同一任务的测量时长。

## 5. RescueBot：反馈、状态机与安全停止 {#rescuebot}

#### 功能流程

1. 设备自检：测距传感器、编码器、电池与急停状态。
2. 接收目标距离与启动命令，检查安全条件。
3. 启动电机并累计里程，反复检查障碍物和异常数据。
4. 障碍、超时、定位异常或断连时立即安全停止。
5. 达到目标距离后停车并启动警示装置。
6. 保存全程数据用于复盘。

学生能独立解释每个条件和传感器依赖，比仅展示程序运行更有意义。

#### 推荐测试表

| 条件 | 试验 | 指标 |
|---|---|---|
| 目标距离变化 | 多组预定距离 | 距离误差 |
| 障碍物 | 不同位置的模拟障碍 | 检出率、漏检率、制动距离 |
| 地面 | 平整、粗糙、低坡度安全区域 | 任务完成率 |
| 重复性 | 同设置运行 20 次 | 成功率、失败归因 |
| 供电 | 不同电池电量 | 持续可用时间 |
| 失效安全 | 人为模拟传感器缺失 | 是否停止并提示 |

假设 20 次完成 18 次，报告 90% 完成率，也要说明两次失败时的条件；单个样本的 90% 不能直接作为可靠性认证。**任何类似道路安全项目只能在封闭、授权场地测试，不在开放道路测试。**

### 状态机伪代码：教学逻辑

仅解释安全逻辑，不能直接用于实物。传感器、制动和急停需独立验证。

~~~text
状态 = IDLE
收到启动命令:
    检查电池、编码器、测距及急停
    如果自检不通过: 进入 FAULT，禁止驱动
    否则: 设置目标距离，进入 MOVING

每个控制周期:
    读取编码器、测距与状态
    如果急停触发、传感器断连、超时或障碍:
        关闭电机，进入 SAFE_STOP，记录故障
    否则如果累计距离达到目标:
        关闭电机，启动警示装置，进入 ARRIVED
    否则:
        限速驱动，记录时间、里程与传感器值

人工确认安全并复位:
    返回 IDLE；禁止故障后自动重启
~~~

## 6. 三个项目的能力比较 {#comparison}

| 维度 | FireAIDSS | Aphelion | RescueBot |
|---|---|---|---|
| Python | 较高 | 中等 | 入门至中等 |
| 数学 | 统计、矩阵、传播建模 | 力学、几何、控制 | 运动学、基础反馈 |
| 硬件 | 无人机、传感器和集成 | 精密执行器/控制台 | 小型机器人 |
| 系统风险 | 飞行、火情误判 | 运动失控、机械失效 | 碰撞、误停车 |
| 建议阶段目标 | 离线模型 + 飞行模拟 | 台架闭环 + 数据测量 | 封闭场地自动任务 |
| 强度评价 | 跨多领域系统工程 | 机电控制深入 | 可范围化的集成项目 |

**这是不同项目形态下的教学分析，不是对获奖团队真实技能水平的评级。**

## 7. 从概念验证到可靠性 {#testing}

验证应从具体功能逐层扩展，保留失败记录。分层是教学框架，不是官方认证。

| 层次 | 回答的问题 | 记录 |
|---|---|---|
| PoC (概念验证) | 核心功能是否可运行 | 输入、代码版本、条件、输出 |
| Performance | 表现如何 | 指标定义、单位、重复次数、平均与波动 |
| Benchmark | 比基准改进多少 | 同工况基准、差异及计算规则 |
| Reliability | 扰动与故障下能否安全工作 | 异常输入、失效处置、失败归因 |

图像分类需记录 TP、FP、FN，并明确正类：


$$
Precision=\frac{TP}{TP+FP},\quad Recall=\frac{TP}{TP+FN},\quad F_{1}=\frac{2PR}{P+R}
$$


其中 $P$ 与 $R$ 分别为 Precision 与 Recall；分母为零时需要明确统计规则，不能输出虚假的满分。预测误差可用 MAE、RMSE，必须说明预测时间跨度及空间单位。

训练与测试分开；不同蜂群、患者、场景或时间段可能需要分组划分，避免同一对象泄漏。没有负例、缺少复杂工况或只剪辑一次成功，都不能证明可靠性。20 次成功 18 次等于该组测试的 90%，不等于安全认证。
